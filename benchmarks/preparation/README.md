# Preparation versus direct assessment

```console
python -m benchmarks.preparation.runner --output .runtime-preparation/new-run
```

The frozen protocol uses 200 synthetic cases in four equally sized families. Both arms share final
governance; the prepared arm adds the real SDK preparation layer. The counting fixture has no artificial
delay. Model calls avoided are workload-dependent, not evidence of a 75% saving in production. No effect
is dispatched. Cases that stop at preparation are compared to expected prerequisite outcomes, not
misrepresented as final authorizations. Both variants can issue simulated permits on eligible cases.

Keep runtime stores/keys private. Publish only manifest.json, summary.json and observations.json.
See `docs/benchmarks/preparation-and-public/summary.md` for measured costs and limitations.
