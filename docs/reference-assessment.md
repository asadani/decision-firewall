# Reference assessment

The four original files in `refer/` are preserved as source material, not treated as a specification or an independently verified evidence base.

| Idea | Decision |
|---|---|
| Intent → choice → permission → consequence | Adopted as the central record and inspection flow |
| Provider-neutral governance | Adopted; fixtures, external outputs, keyword baseline, Laya |
| Trusted evidence and declared objectives | Adopted; local ledger authority is explicit |
| Signed receipts and capability binding | Adopted with limited local integrity claims |
| Confidence-multiplied risk formula | Rejected; certainty must not erase impact or authority constraints |
| Counterfactual output flips prove intent/discrimination | Rejected; sensitivity is an investigation signal |
| Model consensus guarantees correctness | Rejected; independent judges deferred |
| Cedar is mandatory / OPA is order-dependent | Not adopted; actual policy requirements drive engine choice |
| Public transparency log and HSM in MVP | Deferred; local keys and explicit trust limitations |
| Compliance assured by receipts and review | Rejected; no legal certification claim |
| Full enterprise inventory and fairness dashboard | Deferred until real workflows and outcomes justify them |
| Stateful budgets, revocation, concurrency, unknown outcomes | Added as essential execution requirements |
